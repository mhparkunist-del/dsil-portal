# DSIL Lab Portal

KAIST Device-to-System Integration Lab (DSIL) 연구실 **내부 운영 도구** 모음입니다.
빌드 없이 GitHub Pages 에 바로 올라가는 정적 사이트이며, 디자인은 오픈소스 UI 킷 **[Tabler](https://tabler.io/)** (MIT) 위에
DSIL 홈페이지의 KAIST 블루와 상단 스트립을 얹었습니다. 한글 본문은 **[Pretendard](https://github.com/orioncactus/pretendard)** (OFL),
캘린더는 **[FullCalendar](https://fullcalendar.io/)** (MIT) 를 씁니다.

배포 주소: **<https://mhparkunist-del.github.io/dsil-portal/>**

| 도구 | 경로 | 요약 |
|------|------|------|
| 구매 요청 | `budget/` | 구매 요청 → 관리자 과제·비목 배정 → 예산 차감. 구매 심의(가할당), 기간별 조회, 과제 예산 현황, 보고서 내보내기·이력 |
| 구매 보고서 | `report/` | 승인된 구매 건마다 영수증·거래내역·검수 사진을 첨부해 정산용 한글 양식(▶ 영수증 / ▶ 거래내역 / ▶ 기타 정보 표 / ▶ 사진)으로 인쇄·DOCX 출력. 금액·결제 방법에 따라 필요한 첨부를 안내 |
| 장비 예약 | `equipment/` | 캘린더 예약·일정 변경, 사용 후 로그 시트, 로그 기한 초과 시 예약 차단, 장비 담당자의 사용자 등급 관리 |
| 회의비 처리 | `meeting/` | 사용 카드·과제(참여과제 시트)·참석자(과제 참여자만, 1인당 3만원 이하, 자동 추가)로 청구하면 승인 없이 즉시 처리 → 회의록(표 + 영수증) 작성·DOCX |
| 소모품 재고 | `inventory/` | 관리자가 중간 관리자 지정 → 중간 관리자가 품목·보유량·단가 등록/입고 → 구성원이 소모 처리 탭에서 차감 |

출석 시트는 보류 상태로 `archive/` 에 보관되어 있습니다(메뉴에서 제외). 되살리는 방법은 `archive/README.md` 참고.

## 로그인 포털과 계정

- 포털 첫 화면은 **이름 + PIN 로그인**입니다. 로그인해야 2×2 메뉴가 보이고, 로그인하지 않은 채 다른 페이지를 열면 포털로 되돌아옵니다.
- **회원가입 신청**: 이름과 PIN을 정해 신청하면 `승인 대기` 상태가 되고, 관리자가 포털 홈의 가입 신청 목록에서 승인해야 로그인할 수 있습니다.
- **슈퍼계정**: `관리자 / 0000` 이 처음부터 만들어져 있습니다. 관리자는 포털 홈에서 가입 승인·거절, 권한(관리자/구성원) 변경, 사용 중지, PIN 재설정을 합니다.
- 관리자 탭(과제 예산, 각 도구의 관리자)은 **관리자 권한 계정에만 보이고**, 들어갈 때 관리자 PIN(`config.js` `adminPin`, 기본 `0000`)을 한 번 더 묻습니다.
- 공용 DB 모드에서는 이메일 magic link 로 로그인하며, 처음 로그인한 계정은 `pending` 으로 만들어져 관리자가 `profiles.status` 를 승인합니다.

처음 상태에는 **관리자 / 0000 계정만** 있고 다른 데이터는 없습니다. 예시 데이터로 둘러보고 싶으면 `config.js` 의 `seedDemoData` 를 `true` 로 바꾸세요(예시 구성원·장비 담당자·중간 관리자·심의 열람 PIN 은 모두 `1234`).

### 보안: 잠금·매크로 감지·알림

- 같은 이름으로 로그인이 `maxLoginFailures`(5)회 연속 실패하면 `lockoutMinutes`(10분) 동안 잠기고, 잠금 중 시도도 기록됩니다.
- 페이지가 뜬 뒤 `macroThresholdMs`(1.2초) 안에 로그인·출석 체크·장비 예약이 제출되면 **매크로 의심**으로 기록됩니다.
- 기록은 포털 홈의 관리자 화면 **보안 이벤트** 표에 남습니다. `config.js` `security.alertWebhookUrl` 에 Discord/Slack incoming webhook 주소를 넣으면 잠금·매크로 의심 이벤트가 즉시 전송됩니다.
  이 파일은 공개 저장소에 있어 주소가 노출되므로, 노출이 싫으면 공용 DB 모드에서 `security_events` 테이블 INSERT 에 Supabase Database Webhook 을 거는 편이 안전합니다.
- 로컬 저장 모드에서는 기록이 각 브라우저에만 남습니다. 여러 사람의 시도를 한곳에서 보려면 공용 DB 모드가 필요합니다.

### 저장소 보호

- GitHub 저장소는 공개이지만 **쓰기 권한은 소유자 계정 하나뿐**이며, `main` 브랜치에 삭제·강제 push 금지와 Pull Request 필수 규칙(ruleset `protect-main`)이 걸려 있습니다. 소유자는 예외입니다.
- 다른 사람은 fork 후 Pull Request 로만 제안할 수 있고, PR 이 오면 GitHub 이 소유자에게 알림을 보냅니다.

## 과제별 예산 관리 (`budget/`)

| 탭 | 누가 | 내용 |
|----|------|------|
| 구매 요청 | 구성원 | 품명·비목·수량·단가·링크·메모로 요청 제출. 승인된 구매 심의에 연결 가능 |
| 요청 조회 | 구성원 | 기간(이번 달·지난 달·최근 30/90일·올해·전체·직접 입력), 상태, 비목, 과제, 검색어로 조회. 묶어 보기, CSV. 본인 미처리 요청은 수정·취소 |
| 구매 심의 | 구성원 | 구매 건을 나눠 적으면 건별 KAIST 구매 절차 기준 표시. 열람 PIN 으로 내용 보호. 승인 시 과제 예산에 **가할당** |
| 내 과제 예산 | **과제 담당자** | 본인이 담당자로 지정된 과제의 예산 현황만 봅니다. 관리자 PIN 없이 열립니다. 담당 과제가 없으면 탭이 보이지 않습니다 |
| 관리자 · 과제 예산 | 관리자 | 미처리 인박스(배정·반려), 심의 승인·반려, **과제 예산 현황**(과제별·비목별 실집행 / 가할당 / 잔액), 과제 관리, **보고서 내보내기**(승인건 선택 → CSV/인쇄용), **내보내기 이력**(삭제 불가 아카이브) |

- 실집행 = 처리된 구매 요청 합계, 가할당 = 승인된 심의 승인액 − 연결된 실집행. 잔액 = 예산 − 실집행 − 가할당.
- **과제 담당자**: 관리자 탭의 과제 추가·수정 폼에서 `과제 담당자` 에 이름을 쉼표로 적습니다(포털 로그인 이름과 같게). 지정된 사람은 관리자가 아니어도 **내 과제 예산** 탭과 홈 요약 카드(담당 과제 잔액)에서 그 과제의 예산·실집행·가할당·배정 내역을 볼 수 있고, 다른 과제 예산은 보이지 않습니다. 공용 DB 모드에서는 `projects_public` 뷰가 관리자·담당자에게만 `budgets` 를 내려 줍니다(`is_project_owner()`).

### 구매 보고서 (`report/`)

흐름: **구매 요청 → 관리자 승인(과제 배정) → 물품 수령 후 보고서 작성 → 관리자 확인**. 요청 조회의 처리 건마다 `보고서 미작성 / 작성 중 / 제출 / 확인` 배지가 붙고, 배지를 누르면 `report/index.html#id=<요청 id>` 로 들어갑니다. 작성자 본인(또는 관리자)만 쓸 수 있고, 관리자가 확인 완료로 표시하면 잠깁니다.

| 항목 | 내용 |
|---|---|
| 기타 정보 표 | 구매내역 · 금액(영수증 합계) · 계정책임자(과제의 기본값, `config.report.defaultAccountManager`) · 계정(과제명 + 과제번호 예: `G04260010(00)`) · 카드실사용자(결제자, 과제에 등록한 **카드 실사용자 목록**에서 선택) · 실구매자(물품사용자 = 실제로 쓰는 사람) · 검수일자 · 검수자(기본 `defaultInspector`) |
| 첨부 안내 | ≤ 50만원: 영수증·거래내역만 / 50만원 초과 ~ 500만원: **자체 검수** 물품 사진 2장 이상(1페이지 1장) / 500만원 초과: **중앙검수** 안내. 네이버페이는 주문 상세(배송비 포함 결제금액) 캡처가 영수증 합계와 같아야 하며 일치 확인 체크 필수. 세금계산서는 전자세금계산서 + 거래명세서/이체확인증 |
| 주의사항 | 카드실사용자·실구매자는 참여연구원, 실구매자는 실제 사용자. 검수일자는 고가 물품이 도착한 날 = 서류 작성일이 원칙. 계정은 과제 약칭 + 과제번호 |
| 사진 | 브라우저에서 긴 변 1,400px JPEG 로 줄여 저장(local 모드: IndexedDB `dsil-portal-photos`, supabase 모드: Storage 버킷 `report-photos`). 서명 이미지는 페이지 상단 **내 서명**으로 등록하면 표의 이름 아래에 들어갑니다 |
| 출력 | **인쇄용 보고서**(A4, 한글 양식과 같은 순서, 사진은 1페이지 1장) → 브라우저 인쇄/PDF. **DOCX**(JSZip 로 생성, 사진·서명 포함) → 한글에서 열어 hwp 로 저장 가능 |

관리자는 과제 등록 화면에서 **계정책임자**와 **카드 실사용자 목록**을 적어 두고, 배정 화면에서 과제를 고르면 그 목록이 바로 보입니다.
- 구매 절차 기준: 500만원 이하 자체 검수 / 500만원 초과 중앙검수 / 1,000만원 이상 구매팀 / 2,000만원 이상 구매팀 입찰 (`procurementTiers`).
- 비목 기본값 재료비 / 연구활동비 / 장비구매비 / 회의비 / 기타 (`budgetCategories`). 과제를 추가·수정할 때 비목별 예산을 각각 입력합니다.

## 장비 예약 (`equipment/`)

- **캘린더**: 주/일/월/목록 보기, 장비별 색상. 빈 시간을 드래그하면 예약 폼에 채워지고, 내 예약 블록을 끌거나 늘리면 **일정이 바로 변경**됩니다(상세 창의 일정 변경 버튼으로도 가능).
- 시작·종료는 날짜와 시각을 함께 입력하며, 종료가 시작보다 빠르면 자동으로 맞춰지고 제출 시 다시 검사합니다. 휴가·출장 신청의 종료일도 시작일보다 빠를 수 없습니다.
- **사용자 등급**: 장비 담당자가 이름과 등급(**교육 → 유저 테스트 대기 → 유저 → 슈퍼유저**)으로 등록합니다. **유저·슈퍼유저만 예약**할 수 있고 별도 PIN 은 없습니다.
- **사용 로그**: 사용이 끝난 예약은 로그 시트(실제 사용 시간, 장비 상태, 사용 내용, 특이사항)를 작성해야 합니다. `logDueDays`(기본 7일)를 넘기면 새 예약이 막힙니다.
- **장비 담당자**: 장비 + 담당자 PIN 으로 열어 사용자 등록·등급 변경·해제, 예약 변경·취소, 로그 열람·면제.
- **관리자**: 장비 목록, 위치, 담당자, 담당자 PIN, 사용 규칙, 색상, 예약 가능 여부.
- 같은 장비의 시간 겹침, 지난 시간, 최대 시간(`maxHours`)은 저장 전에 막습니다.

기본값(`config.js`): `defaultAccounts` 에 적힌 이름은 처음 열 때 승인된 구성원 계정으로 자동 생성되고(현재 이현진·백승훈·위동진·김형준·음성민·양희수, PIN 0000), `defaultEquipment` 의 장비도 없으면 만들어집니다(현재 프로브 스테이션, 담당자 백승훈, 담당자 PIN 0000, 백승훈 슈퍼유저). 같은 이름이 이미 있으면 건드리지 않습니다. PIN 은 로그인 후 각자 바꾸는 것을 권장합니다.

예약이 안 될 때 확인할 것:

- **장비가 없으면** 예약 폼 대신 "예약할 장비가 아직 없습니다" 안내가 나옵니다. 관리자 탭에서 장비를 추가하세요(담당자 PIN 은 숫자 4~8자리).
- **구성원은 장비 담당자가 유저·슈퍼유저 등급으로 등록해야** 예약할 수 있습니다. 등록된 장비가 하나도 없으면 폼 위에 장비별 담당자 이름과 함께 안내가 뜹니다. 담당자가 없거나 PIN 을 잊었으면 **관리자 탭 아래 "사용자 등록 (관리자)"** 에서 관리자가 PIN 없이 등록·등급 변경·해제할 수 있습니다.
- **관리자 계정(관리자 / 0000)은 등록 없이 모든 장비를 예약**할 수 있습니다(예약 폼에 "(관리자)" 표시). 공용 DB 모드의 `create_reservation` 함수도 같은 규칙입니다.
- 사용 로그를 7일 넘게 안 쓴 예약이 있으면 새 예약이 막히고, 그 사실이 폼 위에 빨간 안내로 나옵니다.

## 출석 시트 (보류 · `archive/attendance/`)

- 현재 메뉴에서 빠져 있습니다. 코드와 데이터 계층, Supabase 스키마는 유지되어 있어 `archive/README.md` 의 절차로 되살릴 수 있습니다.
- 규칙(보관 시점): 출석 가능 시간 `openAfter`(06:00) ~ `closeAfter`(11:00), `lateAfter`(09:00) 이후 지각(사유 입력 시 정상 참작), 11:00 이후 미기입(결근), 주말·공휴일·휴가·출장 제외, 휴가 상·하반기 각 `vacationDaysPerHalf`(2일), 출장은 사유 필수, 관리자 월 시트·공휴일 편집.

## 회의비 처리 (`meeting/`)

- 회의명, 회의 일시, 장소, 참석자(쉼표 구분, 인원 자동 계산), 금액, 결제 방법(우리카드 / 신한카드 / 개인 선결제 / 세금계산서), 비목(기본 **회의비**), 청구 과제(선택), 목적·안건을 적어 청구합니다. 1인당 금액이 입력 중에 표시됩니다.
- 구매 요청과 달리 **관리자 승인 단계가 없습니다.** 청구자가 사용 카드와 과제를 고르고 참석자를 배정해 제출하면 즉시 처리(`status = done`)되어 그 과제의 회의비에서 차감되고, 바로 **회의록** 작성 화면으로 넘어갑니다.
- **참여과제 시트**(`assets/data/participation.js`, 엑셀 `참여과제_YYMMDD.xlsx` 를 `scratchpad/gen_participation.py` 로 변환)가 과제(약칭)와 참여자, 월별 참여 여부(회색 칸 = 미참여)를 정합니다. 처음 열 때 자동으로 가져와 약칭별 과제를 만들고, 관리자 탭에서 새 엑셀을 올려 갱신할 수 있습니다(SheetJS, 회색 채우기 인식). 과제번호(계정)는 구매 요청 관리자 탭의 과제 등록에서 채웁니다.
- 참석자는 **고른 과제의 참여자(회의 월 기준)** 중에서만 고를 수 있고, 시트에 없는 사람은 기타 참석자로 따로 적힙니다. **1인당 `config.meeting.perPersonMax`(기본 30,000원)** 을 넘으면 제출이 막히며, **자동 추가** 버튼이 금액 ÷ 30,000 으로 계산한 최소 인원까지 시트 순서(청구자 먼저)로 채웁니다.
- **과제별 규칙** `config.meeting.projectRules`: 예를 들어 `우수신진: { minNonParticipants: 1 }` 이면 그 과제에 참여하지 않는 연구실 연구원(시트에 있는 사람)을 1명 이상 꼭 포함해야 제출됩니다. 참석자 추가 목록이 "과제 참여자 / 미참여 연구원"으로 나뉘고, 자동 추가가 미참여 연구원부터 채웁니다. 미참여 연구원 칩은 주황색으로 표시되고 회의록·CSV·로그에 따로 적힙니다.
- **처리 로그** 탭: 청구(즉시 처리)·회의록 제출/확인/보완 요청·삭제·시트 가져오기·과제 동기화·약칭 연결·과제번호 변경이 모두 남습니다(추가만 가능, 삭제 없음). 관리자는 전체, 구성원은 자기 청구 관련 로그를 보고 CSV 로 내려받습니다. local 모드 `data.meetingLogs`, supabase 모드 `meeting_logs` 테이블.
- **과제 목록 ↔ 시트 동기화**: 관리자 탭 "과제 목록과 동기화"가 시트의 약칭과 과제 목록을 맞춥니다. 이름이 같거나 한쪽이 다른 쪽을 포함하면 자동 연결(예: "국가반도체 인력양성 사업" ← 국가반도체), 시트에서 자동 생성된 중복 과제는 기존 과제로 병합(청구·요청도 옮김), 시트에 없는 과제는 자기 이름을 약칭으로 갖습니다. 표에서 과제마다 약칭을 직접 고를 수도 있습니다. 시트를 가져올 때도 같은 동기화가 돌아갑니다.
- 회의록(`report/`): 회의일자 · 결제시간 · 회의명 · 회의내용 · 회의장소 · 인원수 · 참석자 · 계정(과제번호) · 사용금액 표와 `* 영수증` 사진. 청구 내용이 미리 채워지고 영수증만 찍어 붙이면 됩니다. 인쇄용(A4)과 DOCX 로 내려받습니다(파일명 예: `432,000원 회의록_0812_우수신진.docx`).
- 청구는 구매 요청과 같은 저장소에 `kind = meeting` 으로 저장되어 요청 조회·보고서·CSV 에도 회의비 배지로 함께 나옵니다. 이전 방식의 미처리 건은 관리자 탭에서 계속 배정할 수 있습니다.
- 청구 내역 탭에서 상태 확인, 상세 보기, CSV 내려받기, 미처리 청구 취소가 됩니다.

## 소모품 재고 (`inventory/`)

- **관리자**가 중간 관리자(이름·담당 영역·PIN)를 둡니다.
- **중간 관리자**가 PIN 으로 열어 품목(분류, 보관 장소, 보유량, 단위, 단가, 최소 수량)을 등록하고 입고·조정합니다. 보유량 변경은 조정 이력으로 남습니다.
- **구성원**은 소모 처리 탭에서 물건을 꺼낸 보관 장소를 고르고 품목·수량·용도를 적어 소모 처리합니다. 재고 현황 탭은 조회 전용입니다. 재고가 즉시 차감되고 이름이 남습니다.
- 최소 수량 이하 품목은 상단 경고와 담당자 탭에 표시됩니다. 재고 금액 = 보유량 × 단가.

## 관리자 PIN 과 열람 PIN

- **관리자 PIN**: 로그인과 별개로 관리자 탭에 들어갈 때 묻습니다(`adminPin`, `adminUnlockMinutes`). 공용 DB 모드에서는 `profiles.is_admin` 인 사람만 이 탭이 보이고 실제 권한은 RLS 가 강제합니다.
- **열람·담당자·사용자 PIN**: 모두 SHA-256 해시로만 저장됩니다. 공용 DB 모드에서는 서버 함수가 해시를 비교하므로 PIN 없이는 동작하지 않습니다.

## 데이터 저장 방식

`assets/js/config.js` 의 `backend` 값으로 고릅니다.

### 1. `local` (기본)

브라우저 `localStorage` 에 저장됩니다. **같은 PC의 같은 브라우저에서만** 보입니다. 예산 관리 관리자 탭에서 JSON 내보내기/가져오기로 전체 데이터를 옮길 수 있습니다.

### 2. `supabase` – 연구실 공용 (권장)

1. [supabase.com](https://supabase.com) 에서 프로젝트 생성
2. SQL Editor 에 `supabase/schema.sql` 전체를 붙여 넣고 실행 (여러 번 실행해도 안전)
3. Authentication → Providers → Email 에서 magic link 활성화
4. Project Settings → API 의 URL 과 anon key 를 `config.js` 에 입력하고 `backend: 'supabase'`
5. 첫 관리자 지정:

   ```sql
   update public.profiles set is_admin = true where email = 'admin@kaist.ac.kr';
   ```

출석 규칙(지각·마감 시각, 휴가 일수, 자동 등록)은 공용 DB 모드에서 `attendance_settings` 테이블에서 바꿉니다.
