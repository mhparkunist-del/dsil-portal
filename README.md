# DSIL Lab Portal

KAIST Device-to-System Integration Lab (DSIL) 연구실 **내부 운영 도구** 모음입니다.
빌드 없이 GitHub Pages 에 바로 올라가는 정적 사이트이며, 디자인은 오픈소스 UI 킷 **[Tabler](https://tabler.io/)** (MIT) 위에
DSIL 홈페이지의 KAIST 블루와 상단 스트립을 얹었습니다. 한글 본문은 **[Pretendard](https://github.com/orioncactus/pretendard)** (OFL),
캘린더는 **[FullCalendar](https://fullcalendar.io/)** (MIT) 를 씁니다.

배포 주소: **<https://mhparkunist-del.github.io/dsil-portal/>**

| 도구 | 경로 | 요약 |
|------|------|------|
| 과제별 예산 관리 | `budget/` | 구매 요청 → 관리자 과제·비목 배정 → 예산 차감. 구매 심의(가할당), 기간별 조회, 보고서 내보내기·이력 |
| 장비 예약 | `equipment/` | 캘린더 예약, 사용 후 로그 시트, 로그 기한 초과 시 예약 차단, 장비 담당자의 사용자 PIN 등록 |
| 출석 시트 | `attendance/` | 아이디+PIN 로그인 → 출석 체크. 지각·참작·결근 판정, 휴가·출장 신청, 주말·공휴일 제외, 관리자 월 시트 |
| 소모품 재고 | `inventory/` | 관리자가 중간 관리자 지정 → 중간 관리자가 품목·보유량·단가 등록/입고 → 구성원이 보관 장소별 소모 처리 |

## 로그인 포털과 계정

- 포털 첫 화면은 **이름 + PIN 로그인**입니다. 로그인해야 2×2 메뉴가 보이고, 로그인하지 않은 채 다른 페이지를 열면 포털로 되돌아옵니다.
- **회원가입 신청**: 이름과 PIN을 정해 신청하면 `승인 대기` 상태가 되고, 관리자가 포털 홈의 가입 신청 목록에서 승인해야 로그인할 수 있습니다.
- **슈퍼계정**: `관리자 / 0000` 이 처음부터 만들어져 있습니다. 관리자는 포털 홈에서 가입 승인·거절, 권한(관리자/구성원) 변경, 사용 중지, PIN 재설정을 합니다.
- 관리자 탭(과제 예산, 각 도구의 관리자)은 **관리자 권한 계정에만 보이고**, 들어갈 때 관리자 PIN(`config.js` `adminPin`, 기본 `0000`)을 한 번 더 묻습니다.
- 공용 DB 모드에서는 이메일 magic link 로 로그인하며, 처음 로그인한 계정은 `pending` 으로 만들어져 관리자가 `profiles.status` 를 승인합니다.

예시 데이터: 구성원 홍길동·이영희·박철수(PIN `1234`), 승인 대기 김신입(PIN `1234`). 장비 담당자·중간 관리자·심의 열람 PIN 도 모두 `1234` 입니다.

### 보안: 잠금·매크로 감지·알림

- 같은 이름으로 로그인이 `maxLoginFailures`(5)회 연속 실패하면 `lockoutMinutes`(10분) 동안 잠기고, 잠금 중 시도도 기록됩니다.
- 페이지가 뜬 뒤 `macroThresholdMs`(1.2초) 안에 로그인·출석 체크·장비 예약이 제출되면 **매크로 의심**으로 기록됩니다.
- 기록은 포털 홈의 관리자 화면 **보안 이벤트** 표에 남습니다. `config.js` `security.alertWebhookUrl` 에 Discord/Slack incoming webhook 주소를 넣으면 잠금·매크로 의심 이벤트가 즉시 전송됩니다.
  이 파일은 공개 저장소에 있어 주소가 노출되므로, 노출이 싫으면 공용 DB 모드에서 `security_events` 테이블 INSERT 에 Supabase Database Webhook 을 거는 편이 안전합니다.
- 로컬 저장 모드에서는 기록이 각 브라우저에만 남습니다. 여러 사람의 시도를 한곳에서 보려면 공용 DB 모드가 필요합니다.

### 저장소 보호

- GitHub 저장소는 공개이지만 **쓰기 권한은 소유자 계정 하나뿐**이며, `main` 브랜치에 삭제·강제 push 금지와 Pull Request 필수 규칙(ruleset `protect-main`)이 걸려 있습니다. 소유자는 예외입니다.
- 다른 사람은 fork 후 Pull Request 로만 제안할 수 있고, PR 이 오면 GitHub 이 소유자에게 알림을 보냅니다.

## 과제별 예산 관리 (`budget/`)

| 탭 | 누가 | 내용 |
|----|------|------|
| 구매 요청 | 구성원 | 품명·비목·수량·단가·링크·메모로 요청 제출. 승인된 구매 심의에 연결 가능 |
| 요청 조회 | 구성원 | 기간(이번 달·지난 달·최근 30/90일·올해·전체·직접 입력), 상태, 비목, 과제, 검색어로 조회. 묶어 보기, CSV. 본인 미처리 요청은 수정·취소 |
| 구매 심의 | 구성원 | 구매 건을 나눠 적으면 건별 KAIST 구매 절차 기준 표시. 열람 PIN 으로 내용 보호. 승인 시 과제 예산에 **가할당** |
| 관리자 · 과제 예산 | 관리자 | 미처리 인박스(배정·반려), 심의 승인·반려, **과제 예산 현황**(과제별·비목별 실집행 / 가할당 / 잔액), 과제 관리, **보고서 내보내기**(승인건 선택 → CSV/인쇄용), **내보내기 이력**(삭제 불가 아카이브) |

- 실집행 = 처리된 구매 요청 합계, 가할당 = 승인된 심의 승인액 − 연결된 실집행. 잔액 = 예산 − 실집행 − 가할당.
- 구매 절차 기준: 500만원 이하 자체 검수 / 500만원 초과 중앙검수 / 1,000만원 이상 구매팀 / 2,000만원 이상 구매팀 입찰 (`procurementTiers`).
- 비목 기본값 재료비 / 연구활동비 / 장비구매비 / 기타 (`budgetCategories`).

## 장비 예약 (`equipment/`)

- **캘린더**: 주/일/월/목록 보기, 장비별 색상. 빈 시간을 드래그하면 예약 폼에 채워지고, 내 예약 블록을 끌거나 늘리면 **일정이 바로 변경**됩니다(상세 창의 일정 변경 버튼으로도 가능).
- 시작·종료는 날짜와 시각을 함께 입력하며, 종료가 시작보다 빠르면 자동으로 맞춰지고 제출 시 다시 검사합니다. 휴가·출장 신청의 종료일도 시작일보다 빠를 수 없습니다.
- **사용자 등급**: 장비 담당자가 이름과 등급(**교육 → 유저 테스트 대기 → 유저 → 슈퍼유저**)으로 등록합니다. **유저·슈퍼유저만 예약**할 수 있고 별도 PIN 은 없습니다.
- **사용 로그**: 사용이 끝난 예약은 로그 시트(실제 사용 시간, 장비 상태, 사용 내용, 특이사항)를 작성해야 합니다. `logDueDays`(기본 7일)를 넘기면 새 예약이 막힙니다.
- **장비 담당자**: 장비 + 담당자 PIN 으로 열어 사용자 등록·등급 변경·해제, 예약 변경·취소, 로그 열람·면제.
- **관리자**: 장비 목록, 위치, 담당자, 담당자 PIN, 사용 규칙, 색상, 예약 가능 여부.
- 같은 장비의 시간 겹침, 지난 시간, 최대 시간(`maxHours`)은 저장 전에 막습니다.

## 출석 시트 (`attendance/`)

- 포털 계정으로 자동 연결됩니다(같은 이름의 출석 구성원이 없으면 생성).
- 출석 체크 가능 시간은 `openAfter`(06:00) ~ `closeAfter`(11:00) 입니다. `lateAfter`(09:00) 전 정상, 그 뒤 11:00 전까지는 지각(사유를 적으면 정상 참작), 11:00 이후 ~ 다음날 06:00 은 체크 불가이며 그날은 미기입(결근).
- 주말·공휴일·휴가·출장일은 체크하지 않으며 로그에 그대로 표시됩니다. 공휴일 목록은 `config.js` 초기값을 관리자 탭에서 편집합니다. **매년 확인해서 갱신하세요.**
- 휴가는 상반기(1~6월)·하반기(7~12월) 각 `vacationDaysPerHalf`(2일). 근무일만 계산하며 초과 신청은 막습니다. 출장은 사유 필수.
- 관리자: 월별 전체 시트(○ 정상 ◇ 참작 △ 지각 × 결근 휴 출 공), 칸 클릭으로 수정, CSV, 구성원 추가·PIN 재설정·중지, 공휴일, 휴가·출장 전체.

## 소모품 재고 (`inventory/`)

- **관리자**가 중간 관리자(이름·담당 영역·PIN)를 둡니다.
- **중간 관리자**가 PIN 으로 열어 품목(분류, 보관 장소, 보유량, 단위, 단가, 최소 수량)을 등록하고 입고·조정합니다. 보유량 변경은 조정 이력으로 남습니다.
- **구성원**은 소모 처리 탭에서 물건을 꺼낸 보관 장소를 고르고 품목·수량·용도를 적어 소모 처리합니다. 재고 현황 탭은 조회 전용입니다. 재고가 즉시 차감되고 이름이 남습니다.
- 최소 수량 이하 품목은 상단 경고와 담당자 탭에 표시됩니다. 재고 금액 = 보유량 × 단가.

## 관리자 PIN 과 열람 PIN

- **관리자 PIN**: 로그인과 별개로 관리자 탭에 들어갈 때 묻습니다(`adminPin`, `adminUnlockMinutes`). 공용 DB 모드에서는 `profiles.is_admin` 인 사람만 이 탭이 보이고 실제 권한은 RLS 가 강제합니다.
- **열람·담당자·사용자 PIN**: 모두 SHA-256 해시로만 저장됩니다. 공용 DB 모드에서는 서버 함수가 해시를 비교하므로 PIN 없이는 동작하지 않습니다.

## 데이터 저장 방식

`assets/js/config.js` 의 `backend` 값으로 고릅니다.

### 1. `local` (기본)

브라우저 `localStorage` 에 저장됩니다. **같은 PC의 같은 브라우저에서만** 보입니다. 예산 관리 관리자 탭에서 JSON 내보내기/가져오기로 전체 데이터를 옮길 수 있습니다.

### 2. `supabase` – 연구실 공용 (권장)

1. [supabase.com](https://supabase.com) 에서 프로젝트 생성
2. SQL Editor 에 `supabase/schema.sql` 전체를 붙여 넣고 실행 (여러 번 실행해도 안전)
3. Authentication → Providers → Email 에서 magic link 활성화
4. Project Settings → API 의 URL 과 anon key 를 `config.js` 에 입력하고 `backend: 'supabase'`
5. 첫 관리자 지정:

   ```sql
   update public.profiles set is_admin = true where email = 'admin@kaist.ac.kr';
   ```

출석 규칙(지각·마감 시각, 휴가 일수, 자동 등록)은 공용 DB 모드에서 `attendance_settings` 테이블에서 바꿉니다.

## GitHub Pages 배포

Settings → Pages → Source: Deploy from a branch, `main` / `(root)`. `main` 에 push 하면 1~2분 뒤 반영됩니다.
